# M1.5 Interactive Evaluation Workbench

M1.5 makes the completed M1 evaluation kernel directly inspectable without changing its
evidence model. The web application is a typed API consumer; verdicts and digests remain
backend-owned facts.

## Capabilities

- Displays live API, PostgreSQL, RabbitMQ, Redis, and MinIO readiness.
- Edits and validates a complete `ProblemDefinition` JSON document.
- Runs deterministic accepted, wrong-answer, and compile-error mock scenarios.
- Displays run identifiers, evidence levels, pass ratios, per-case verdicts, durations, and
  input digests.
- Explains the planned mutation, solver, sandbox, and failure-analysis loop.
- Supports responsive desktop/mobile layouts and dark/light presentation themes.

## Runtime architecture

During development, Vite proxies `/api`, `/health`, and `/openapi.json` to the FastAPI
service on port 8000. The production image compiles static assets in a pinned Node.js build
stage and serves them from Nginx. Nginx proxies the same paths, plus `/docs` and `/redoc`, to
the Compose `api` service. This same-origin design avoids browser CORS expansion.

## Quality gates

```bash
cd web
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

The production stack is validated with:

```bash
docker compose config --quiet
docker compose up -d --build
curl -fsS http://127.0.0.1:3000/health/ready
```

## Scope boundary

The three M1 scenarios are deterministic mock demonstrations. They do not execute generated
source and must not be reported as empirical model results. Provider adapters, real sandbox
execution, mutation operators, experiment manifests, and counterexample reduction remain M2
work. Authentication, persistent projects, historical dashboards, and report export remain
part of the later website expansion.
